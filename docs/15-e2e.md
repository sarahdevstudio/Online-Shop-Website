# 15 — Browser end-to-end suite and security headers

## The suite

`storefront/e2e/*.e2e.ts`, Playwright (Chromium), run with `npm run e2e` in `storefront/`. It drives a **running** stack and changes data
(a product name that it restores, a product and a category path, one blog post it deletes, an order), so use a development or
staging database, never production. The specs share one database and run one after the other in file order:

| Spec | What it proves |
|---|---|
| `01-csp` | Every main shop page (home, category with and without a sort, product, cart, blog, search, account, a post, an info page) and every admin page loads with status 200, a heading, a nonce policy, no violation, no uncaught error and axe clean; an inline script without the nonce is refused. |
| `02-checkout` | Add to cart, bad mobile number → Persian error with the typed values kept, order placed, order page (token URL, noindex), empty cart afterwards. |
| `03-admin` | No session → login; wrong password; the order list and detail, advancing the status; a product edit appears on the shop at once and is put back. |
| `04-routing` | Old URLs keep working, 308 redirects keep the query string, conflicts and reserved paths are refused in Persian, a deleted post answers 410, released paths 404 (ported from `smoke-routing.cjs`). |
| `05-entity-links` | Entity links in the menu and footer show the current path, are hidden while the target is a draft or deleted and name it in the editor, return when published (ported from `smoke-entity-links.cjs`). |

Every test also runs the **watcher** in `e2e/fixtures.ts`: a CSP violation, a Permissions-Policy parse warning, an uncaught exception or a
failed script/style/font/image request on *any* page it opens fails the test, whichever flow loaded the page. `axeCheck` (axe-core, WCAG
2.2 A/AA + best practices) fails on any violation, serious or not.

### Running it locally

```bash
# API in Development (sample catalog) with an admin, and the production storefront (see README and docs/09 for the variables)
cd storefront && node scripts/perf/seed.mjs        # the blog post the specs open (needs API, ADMIN_USER, ADMIN_PASS)
BASE=http://localhost:3000 API=http://127.0.0.1:5167 ADMIN_USER=… ADMIN_PASS=… npm run e2e
```

In CI the job `e2e` starts a throwaway SQL Server, the API and the storefront, installs Chromium and runs the suite; the HTML report and
failure traces are uploaded as the `playwright-report` artifact.

## Content-Security-Policy and Permissions-Policy

Set per request by `storefront/src/proxy.ts` (`src/lib/csp.ts`). Every page is rendered on demand already, so a nonce costs no static rendering.

- `script-src 'self' 'nonce-…' 'strict-dynamic'`: Next tags its own scripts with the request's nonce (the proxy passes it on the request headers); no `unsafe-eval` and no `unsafe-inline` in production. The development server adds `unsafe-eval` (React) and websockets.
- `style-src 'self' 'nonce-…'`: the theme `<style>` (and the admin theme preview) carry the nonce. Inline `style=""` attributes need `style-src-attr 'unsafe-inline'` (a nonce cannot be put on an attribute); element styles cannot be inline.
- `img-src 'self' data: blob:`, `font-src 'self'`, `connect-src 'self'`, `media-src 'self'`: product photos come through the same-origin `/media` route.
- `object-src 'none'`, `base-uri 'self'`, `form-action 'self'`, `frame-ancestors 'none'` (with `X-Frame-Options: DENY`).
- `Permissions-Policy` switches off camera, microphone, geolocation, payment, USB, sensors and the other features the shop never uses.
- JSON-LD blocks are `type="application/ld+json"` data, which CSP does not execute, so they need no nonce.
- A third party (for example an analytics tag, added in a later series) joins the policy by name through `CspExtra`, only when the owner configures it.
